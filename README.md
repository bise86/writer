# EssayLens 作文批改 App

EssayLens 是一个 React Native + TypeScript 应用，同一套业务代码面向 Android、iOS 和 HarmonyOS。它把作文照片经过逐页视觉识别、携带原图复核和结构化评分，结果保存到本机 SQLite，并在详情页展示总体评分、五个分项、优缺点、改进建议和原文批注。

## 功能

- 首页展示“作文批改”“英文批改”和同级“挑战”三个入口，从顶部按每行两列排列，第三个入口自然换行。入口采用原生图标和文字，支持按压反馈与系统字体缩放。

- “挑战”首页提供“开始试卷升华”和最近记录；支持连续拍照、相册多选与逐张裁剪，每份试卷最多导入一个 PDF，按选择顺序保存并进入待解析详情；空白和已作答的试卷均可。扫描 PDF 先在本机逐页渲染，再由视觉模型识别印刷试题，剔除学生作答、勾选及批改。非试卷会拒绝；局部解析失败或内容不完整的题在原位置保留原图，不阻断其它题升档，也不猜补条件。
- 挑战先分析原卷科目、学段、题型、知识范围、分值和难度，再选升1／2／3档。难度是按原题条件估计，非实测正确率。各科标准在 [`src/assets/challenge-rules.json`](src/assets/challenge-rules.json)，说明和量化表在 [`docs/挑战试卷升档规则.md`](docs/挑战试卷升档规则.md)，覆盖数学、英语、语文、物理、化学、生物、历史、地理、道德与法治/思想政治、科学及其他学科。
- 逐页识别后先解析完整原卷草稿，先仅从真实印刷标题初判科目，再从固定随机题池抽最多3道不同小题核验；无标题或标题不能识科时直接用3道样题识科，初抽一致即可确认；不一致时每次只追加1题，出现超过已抽题总数一半的明确课程票才停止。未知票留在分母，必要母题与前问只作上下文、不另计票；标题初判需经过样题核验；原标题缺失或无法判科不自动扩大整卷。保存完整题池顺序、题号、逐题票和原锚，重试不换题。识科确认后按科加载规则，再核对完整知识范围与原卷难度；真实混科仍需按科拆分，局部内容缺失则原样保留。
- 五角色在标准制定时评审各科三档指标与边界，发现的问题已修复并记录于 `standardReview`。新卷按设置的圆桌人数评审：0保留基础综合校核，3由命题与范围、难度与掌握、答案与图文三角色独立检查，5进一步拆为命题、范围、难度、答案、呈现五角色。每席读取同一候选版本与本科完整规则，只对实际升档题给票；对应原题仅作对照，保留原题与听力不发起模型评审。没有升档题时不调用模型评审、不伪造角色通过票；有升档题且本轮配置角色全部通过才发布两份PDF，任一异议汇总修复后由原人数全部重审，最多3轮仍不过则不发布。人数与运行协议在生成开始保存快照，设置变化仅影响下一次生成，逐轮/逐角色记录保留，旧卷沿历史基础校核。新题保持原题号、题型、题数、分值、选项标签和核心知识点集合，不能靠超纲、删考点、只改标点或虚报数字升级；单题不适宜变式可保留；因解析异常比例不足时仍正常完成，展示真实升档比例。
- 挑战标准 v3 在11科80个深化方向上增加具体知识点的易错难点目录与逐核心五维掌握训练，参考官方中高考/选考命题分析。数学12方向加强奥数式策略思维：逆向、整体、构造、分类、对称、等价、极端、不变量、表征、反例、存在唯一与路径选择，允许用原核心知识形成更短巧解。组合路线三档至少1/2/3个实质加强方向、0/1/2条联系且全部方向连通；数学2/3档可改用单策略深挖，至少1个方向、2/3个不同关键决策、1/2个真实边界检查。阈值是项目训练标准，不是官方难度系数。
- 各科另有本科知识领域、具体错误机制、三档质量目标、掌握验收、题型设计和范围排除规则，共103项知识点级训练目录。完整JSON是维护源，修改后运行 `npm run sync:challenge-rules` 同步索引与11科模块；`npm test` 和 `npm run typecheck` 会先检查派生文件与源逐字一致，避免运行包与已审标准漂移。
- 已升档题的每个原核心知识点都须在答案学习说明中讲清原理与条件、推理依据、可能错解与纠正、同知识迁移及可执行自检。三档按每题整体至少1/2/3个不同错误来源、1/1/2个迁移对照、1/2/3类自检，跨核心共享内容只计一次；3档同时有原→新迁移和条件反事实，以及条件/推理/结果三类检查。目录按原题子核心、任务和学段筛选，不能由整章名解锁新知识；缺项时须用原题引文定制并校核。答案PDF呈现学习说明，题卷与答案侧内容隔离；成功生成只表示训练覆盖，个人掌握需后续作答与订正验证，学生原作答不用于推断个人错因或掌握率。
- 其它学科增加语篇推断与语用、证据限度、模型适用、竞争解释、实验识别、守恒耦合、尺度转换与多目标权衡等原任务适用方向。每个方向须给原→新要求对照、实际题文/对应解析引文与具体解题作用；结构校验和独立综合校核同时验证，不能只贴标签。作文要求相对原题实质加强，选择/填空不新增证明小问，推理证据放在答案解析。英语听力题及材料原样保留，没有原录音或可核验转写时答案明确待核，不猜答案、不拿学生填答当真值。
- 挑战按输出预算分批生成，只返回本批实际升档题及其答案、确实修改的材料或图；未变题由本地按原ID和原位置补回，不重复要求模型返回原题正文。多题输入超限或输出截断时只拆小当前批，不拼接半截JSON，也不降低单题标准或思考设置。按前问依赖生成，前问或共享条件变化会同步返修受影响升档题，原题回退会清除变式答案。生成、返修及引文修复分别保存待做清单与可信正文，失败/停止后同卷同档可继续；重新解析或改变档次不复用旧草稿。五角色实现评审与修复记录见 [`docs/reviews/challenge-generation-audit.json`](docs/reviews/challenge-generation-audit.json)。
- 升档前在本地按20%/40%/65%初选非听力题，只把选中题交给模型命题、求解和评审；选中题无法可靠升级时才按差额补选，达到比例即停止。未选原题直接保留，不追加模型定位、答案或评审请求，必要前问和共享材料仅作上下文。缺少题框时本地保留原页；断点保存已选范围，旧全题队列仅继续必要工作。
- 挑战引文按原题、新题和独立解析分别溯源。排版差异可还原为真实连续原句；实质引文错误按题号与字段单独修复，再完整校验和评审，不重写整卷。学习说明、其它题或裸答案不能自作依据；无法可靠取证时重新核实原解法，不能靠追加学习说明到解析过关。
- 挑战11科目录统一按原学段、原任务及每个原核心知识点筛选，生成和评审只收到适用目录及逐核心ID白名单；目录缺项允许据原题定制并提供范围理由和真实原句。错选目录时只修该字段，目录与引文修复均可断点继续；实质超纲仍须修订题目，不能改学段、换ID或跳过校验。报错会列出题号、原核心、当前学段和可用ID。
- 挑战校核指出问题后会修订并重新检查，连续仍不合格则不发布 PDF。通过后生成独立的试卷和答案 PDF，可在 App 内切换预览、缩放，并用系统文件选择器下载到所选位置。原图框含学生标记时必须重建图，干净图也先真正裁切再嵌入，试卷 PDF 不暗藏整页原作答。模型负责升档题的实际学科判断，程序核对整卷完整性、原题保留、结构、引用、指标与答案对应关系。
- 按非听力小题总数计算，升1/2/3档分别至少20%/40%/65%题实质升档，题数向上取整。听力不参与分母或分子；非听力保留题仍计入分母。升档题维持本科本档的深度与掌握标准，其余题可原样保留，题干、选项、共享材料/图和必要前问不暗改；局部解析存疑、失败或原印刷不完整的题均按原位置保留，不要求先补充才能继续。保留题无法可靠解答时，答案PDF明确标注待核。覆盖协议另存为 `challenge-selection-v2`。
- 挑战使用独立本机 SQLite 记录及持久文件目录，记录标准版本、逐次模型调用和校核修订；取消、失败或重启可从已保存内容重试。两个 PDF 都写入成功后才发布，候选修改后旧校核失效，删除后迟到结果不会复活记录。系统设置仅清缓存，不删除已保存的挑战。
- 挑战顶部的“管理”进入独立管理页，支持逐条选择、全选、批量删除和按 7/30/90 天清理；最近挑战只保留打开入口。正在补充页面的原记录暂不可删除，确认删除正在处理的挑战会先停止其请求。
- 挑战任务独立于页面存续：应用运行期间返回首页、进入设置或切换其他记录，解析、生成和评审继续执行并保存进度；重新打开可查看最新进度或主动停止，同一份试卷的重复操作不会重复发送任务。
- 挑战详情在适中字号标题下直接展示原卷，原卷下依次是解析按钮、默认1档的难度下拉和升档按钮，再下方是“试卷分析 / 升档方案 / 试卷预览 / 答案预览 / 消耗详情”页卡；逐题分析、难度分布和知识范围集中在分析页，升档方案只展示当前档次的概括思路，完成后列出升档题号、调整说明及保留原因。消耗详情在有实际调用后显示，尚未请求时隐藏。已成功解析的试卷可以直接升档，业务校验问题会明确提示；再点解析先确认“继续解析”或“重新解析”，继续解析复用已识别页面，重新解析重新识别全部原卷。与作文共用消耗展示组件，提供累计总量、解析/出题/评审/修正的阶段统计和逐次调用的模型、状态、耗时及输入/输出/缓存/思考 token，包含失败与重试，缺失字段仍显示“未返回”。

- 拍照或从相册选择作文图片。
- 支持连续拍摄、多选作文页，逐页进入裁剪界面：拖动四角调整裁剪框、拖动框内移动选区，也可点击“原图”保留整张照片。保存失败留在编辑界面重试；取消导入会清理尚未入库的图片。图片会复制到应用文档目录，避免相机临时文件被系统回收。
- 按上传顺序逐页看图识别，每页完成后保存阶段输出；移除本地 ML Kit OCR，避免不可靠的本地文字混入原文。
- 逐页识别和原图复核都按段首缩进、留白和行间关系还原自然段：段内纸面折行连接，段间空一行，确认跨页续段后才合并。复核说明包含正文段数及不确定的段界；原文页按段落分别展示。保留学生原有错字，不润色原文；无法辨认处标明【辨认不清】。不再使用固定的虚假置信度。
- 中文批改按学段加载 `src/assets/scoring-rules.json`（初中）或 `src/assets/high-scoring-rules.json`（高中），英文批改加载 `src/assets/english-scoring-rules.json`（初中）或 `src/assets/high-english-scoring-rules.json`（高中）；两种模式都输出 100 分总评、分项分数、五档结果、优缺点、建议和可定位批注。
- 系统设置中的“圆桌评审角色数量”可选0（默认关闭）、3、5，作文与挑战共用人数。作文沿原提示词内角色讨论及最终评分JSON流程；挑战则真实独立调度对应角色，保留每席报告和异议，修复后全员再审。多页图题或JSON纠正可令同一角色有多次请求，但只合并为该席一份报告，不把页数或重试算成额外角色。原有校验、上下文纠正和SDK重试继续适用；已完成作文可从阶段输出页重新评分与批注。
- 云端图片识别、文字校对与评分共用设置中的同一个模型，模型需要支持图片输入。识别质量依赖照片清晰度与模型的手写视觉能力。
- 使用 OpenAI SDK Responses API，思考级别通过 `reasoning: { effort: "none" | "low" | "high" | "max" }` 传递。关闭对应 `none`，不同模型对级别的支持以服务商为准。
- 上下文大小用于 App 的请求预算，不会扩大模型实际容量，也不会作为不存在的 `model_context_window` 请求参数发送。OpenAI 官方 GPT/o 系列请求传入 `context_management[].compact_threshold`，由上下文大小乘以设置比例计算，同时预留输出和安全余量。
- 压缩仅处理明确传入的历史参考文字。OpenAI 官方服务使用标准 `responses.compact`；DeepSeek 和其他兼容服务使用普通 Responses 请求分段生成历史摘要，不调用专用压缩接口。原生接口不存在时也可回退历史摘要，鉴权错误不会被当作兼容问题忽略。
- 作文原文、图片和评分规则始终完整传递。当前流程的每次请求都是独立任务，通常没有需要压缩的历史；达到阈值而无历史时保持原文，必需内容超出输入预算则明确失败。压缩有收敛检查、轮数及请求数量上限，失败不会覆盖原始记录。
- 文本按 UTF-8 字节数保守估算，图片单独预留预算，不按 Base64 长度计算文本 token。OpenAI 接近阈值时优先使用服务端 token 计数；压缩后的加密内容必须经服务端计数。DeepSeek 的估算不是精确 tokenizer，最终限制仍由服务端校验，超限不会通过静默截断绕过。
- API 地址、API Key、模型名称、思考级别、上下文大小、压缩阈值、输出长度、重试次数均可在系统设置中修改。输出长度可选 4K、8K、16K、32K、64K，默认 32K；重试次数为 0 时不重试，默认 1 次。
- 系统设置中的“评分学段”可选初中（默认）或高中。学段会保存到作文、评分记录和规则版本；切换后新作文及重新评分使用所选学段，旧记录仍保留原学段。
- 初中和高中评分相互独立，只把本篇原文和当前学段的完整细则发送给评分模型，不读取、换算或沿用另一学段分数。高中中文强化版保留原有概念关系、独立判断、材料分析、论证链及准入要求。英语 v4 在中考、高考英语的任务、内容、语言和篇章原则上，较 v3 常规训练要求整体提高一个能力档次，细分60—69、70—79、80—89、90—96、97—100五个强化档，低于60分标为未达强化及格。初高中各有25组分项矩阵，逐档规定达标表现、优点、允许不足和改进方法；高中增加8项按题型适用的能力。第三档以考试满分级完成度为训练质量目标，第四、第五档继续提高，不将其当成官方分数或实际满分承诺。
- 英语强化评分固定真实分项合计，再核对分项底线、文字准入和最高可入档上限，以 `admissionAdjustment` 单列有原文依据的封顶，不为凑档改分项或重复扣分；轻微疏漏不一律封顶79。每项 `qualificationEvidence` 必须逐字引用本篇原文并说明达标或差距，程序核验引用真实性及分数一致性。高中更高的分项底线可能使档次区间低端不可直接取得，应按门槛降档，不能抬分凑档。历史记录保留原值与规则版本，新英语评分只恢复同学段、同规则版本的失败输出；详情和报表注明版本，混合标准的分数不宜直接比较。
- 默认 API 地址为 `https://api.deepseek.com`，统一云端模型为 `deepseek-flash`，上下文为 1M（1,000,000 token）。思考默认 `high`，可选 `none`（关闭）、`low`、`high`、`max`。升级时迁移旧默认值和 `medium`，保留自定义主模型并删除旧的独立 OCR 模型配置。
- 默认不预置 Token；首次使用前请在系统设置中填写你自己的 API Key。密钥只保存在设备本地，不应提交到代码仓库。
- 重试按每次 SDK 请求计数，关闭 SDK 内置重试以免叠加；只重试临时网络错误、408/409/429 和 5xx。鉴权、参数错误及输出截断会明确失败，不重复发送相同的无效请求。页面展示处理、历史压缩和重试进度，手动重试从未完成的步骤继续。
- 空结果、截断、错误 JSON、无效分数或引用原文不存在句子的批注不会保存为成功结果，不生成替代分数。
- “消耗详情”显示本篇作文累计总量、各阶段用量与可展开的逐次调用。每次实际 SDK 请求单独保存，包括多页识别、网络重试、格式纠正、兼容回退、历史摘要/压缩与输入计数；阶段重试追加记录，不覆盖旧消耗。SQLite `model_calls` 保存调用 ID、作文 ID、处理批次、阶段、操作类型、模型、状态、开始/结束时间、耗时、服务端 usage 原始数据和输入/输出/缓存读取/缓存写入/缓存未命中/思考 token。`model_usage_by_stage` 与 `model_usage_by_essay` 视图从明细汇总，避免维护两份累计数。计数接口的测量值单独保存，不加入生成用量。
- 消耗只采用服务端实际返回值；缺失字段存 NULL，显示“未返回”，部分缺失时标出缺失次数，不伪造为 0。缓存读取与思考用量属于输入/输出的分项，不重复加入总 token。缓存未命中与写入量分开：参考 [DeepSeek 缓存说明](https://api-docs.deepseek.com/zh-cn/guides/kv_cache/) 和 [OpenAI 缓存说明](https://developers.openai.com/api/docs/guides/prompt-caching)。旧版未记录的调用无法补算；应用被关闭时未完成的调用保留为“请求中断”。
- SQLite `score_records` 按每次成功评分保存总分、五项数值、档次、评分时间、模型、圆桌人数、规则版本与完整 JSON，可按时间查询历史；`is_current` 标记当前结果。数字与作文结果在同一条 SQLite 语句的触发器中原子保存。已有作文迁入可核验的分数，旧时间标记为 `legacy_updated_at`，不伪造精确评分时间或原模型。单篇、批量及按时间删除作文时，同步删除调用与评分记录，迟到的模型回复不会重新生成孤立记录；设置中的日志清理不会删除统计。
- “作文管理”支持逐条选择删除、批量删除，以及按 7/30/90 天清理旧作文；删除会同步处理识别结果、评分批注、流程步骤、日志和图片。
- 进入批改类型后，“管理”旁的“报表”默认查看最近一个月，可通过日历或日期输入选择起止日期（本机时区，包含结束日全天）。每篇作文取时段内最后一次成功评分，展示作文篇数、平均/最高/最低总分、可切换总分及五项分数的趋势柱状图，以及五项平均分条形图；点击柱形可查看该次分数并打开作文。报表直接查询 SQLite 历史评分，重试不重复计入，删除作文后同步移除；旧版评分时间缺失时明确标记为当时的保存时间。
- 详情页使用“原文 / 阶段输出 / 评分结果 / 批改 / 消耗详情”五个页卡。原始照片以白色卡片内的大图横向列表展示，位于标题下方、页卡上方，识别前即显示并在切换页卡时保留；点击进入全屏，支持双指缩放、放大后拖动、双击缩放及左右切换照片。原文在复核完成后出现并位于首位；处理时展示阶段输出，成功后自动显示评分结果。标题随最新识别及原图复核结果更新。
- 评分结果以浅色总评开头，接着展示所有分项分数，再展示各项优缺点、改进方法、整体优点、不足和下一步建议。批注要求覆盖标题、英文书信称呼（如有）和每个正文段落，并引用原文定位。
- 批改页本地生成双栏 PDF：左侧按顺序完整展示原文一次，右侧对应段落评价和编号句子批注；亮点用绿色、问题用红色、改进处用棕色字体及下划线标记。标题单独评价，英文书信称呼单独评价，正文从第 1 段编号。页面按两栏内容适配高度并保持正常字号；极长内容分页接续，不重复原文，也不用“前页已展示”代替内容。预览按宽度适配、可滚动缩放，与导出使用相同文件；旧记录打开即可使用新布局。
- PDF 使用 pdf-lib + fontkit 生成，react-native-pdf 预览，react-native-share 导出；三端共用业务代码，鸿蒙对应组件已在工程中手动注册。内置 Noto Sans SC 字体（SIL OFL，许可证在 src/assets/fonts/OFL.txt），无需联网下载字体。字体未覆盖的罕见字符以 Unicode 编号显式保留。PDF 位于应用缓存，可由系统设置清理，删除作文也清除其批改缓存。
- 评分 JSON 不符合规则时，会保留作文、上一轮模型输出和具体校验反馈，自动追加纠正请求并继续生成完整结果；连续多轮仍不合格才保留失败状态，原始输出上下文不丢失。
- 启动时会显示本地数据库准备阶段；若数据库迁移或读取失败，会显示具体错误和“重试启动”，不会继续显示无期限的白屏转圈。
- 系统设置只清理应用日志与临时缓存，不会删除作文、图片、API/模型配置或评分 JSON。

## 本地运行

```sh
npm install
npm start
npm run android
# iOS 需要在 macOS 上先执行 bundle exec pod install
npm run ios
```

当前依赖的 OpenAI Node SDK 要求 Node.js 22 或更高版本。Android 发布工作流会在构建前执行类型检查、无警告 lint 和完整测试。

首页可切换“作文”和“英文作文”两种批改类型。中文细则文档为 [`docs/万唯高分作文名校模考_考场高分技法_分析与评分细则.md`](docs/万唯高分作文名校模考_考场高分技法_分析与评分细则.md)（初中版）和 [`docs/高中作文强化评分细则.md`](docs/高中作文强化评分细则.md)（高中版）；英语细则文档为 [`docs/英语作文强化评分细则.md`](docs/英语作文强化评分细则.md)（初中版）和 [`docs/高中英语作文强化评分细则.md`](docs/高中英语作文强化评分细则.md)（高中版）。中文标准保持原样。英语 JSON 单列中考地方分值实例、高考15分应用文五档及25分读后续写七档参考，并记录来源与适用范围；App 的100分、强化五档、底线和提高一档的校准属于项目自定，不等同或机械换算为考试原始分。英语拔高体现在任务针对性、信息与细节价值、语言控制、连贯和语体分寸，不强制通知写哲理、每篇用固定数量的复杂句或续写必须反转。缺少原题、材料和原图时标记“待核题、待核材料、待核原图，训练预评”，不因材料缺失扣分或自动封顶。

HarmonyOS 工程在 `harmony/`，用 DevEco Studio 打开；Metro 配置已经合并 RNOH。同步 entry 的 HAR 依赖后构建；PDF 预览使用 PDFKit，需具备该能力的 HarmonyOS SDK 和设备。

挑战的 PDF 导入/下载包含新增原生 `ChallengeDocuments` 桥，需要重新构建安装包。Android 使用系统文档选择器与 PdfRenderer，iOS 使用 UIDocumentPicker 与 PDFKit，HarmonyOS 使用系统文件选择器与 PDFKit；注册文件已纳入三端工程。每次最多50页、80MB，渲染长边2048像素；加密、损坏或超限时明确失败，不截断。JavaScript、数据校验与 PDF 内容测试不替代设备上的文件权限、系统保存面板及原生编译验收；本容器没有 Android SDK、Xcode 和 DevEco SDK，三端原生构建/真机流程需在相应开发环境执行。

## 发布规则

- `.github/workflows/release-android.yml` 只响应 `v*` tag，构建 release APK 并上传到 GitHub Release。
- Android 正式包使用本 App 独立的固定签名密钥，别名为 `essaylens-release`。每次构建只从 Actions Secrets 还原同一份密钥，结束后删除临时副本；发布流程不生成新密钥。
- 公共证书指纹保存在 `android/signing/release-certificate.sha256`。缺少密钥、证书不符或 APK 验签失败时停止发布；禁止回退调试签名。本地 release 构建也执行同样的校验。
- 正式密钥应保存在仓库外的私有目录，证书有效期约 100 年。整个目录需要独立备份，尤其是 `.p12` 和密码文件；这些私有文件不提交 Git。当前旧安装包使用调试证书，首次换签不能直接覆盖安装，需先处理本地作文数据。
- iOS 与 HarmonyOS 发布模板保存在 `.github/release-templates/`，不属于 GitHub 活跃工作流，不会触发。模板预设仅 `v*` tag 触发并禁用作业；后续配置签名和分发凭据后，再移入 workflows 并启用。

首次创建一份全新的签名密钥时，在仓库根目录运行以下命令；已有私有密钥目录时脚本会拒绝覆盖：

```sh
bash scripts/create-android-signing.sh
```

需要本机安装 Java 的 `keytool` 和 Python 3。脚本默认保存在 `$HOME/.local/share/essaylens/signing/`（设置了 `XDG_DATA_HOME` 时使用该目录下的 `essaylens/signing/`），目录已存在就停止，避免替换旧密钥。它生成一份 PKCS12 密钥、随机长密码、Base64 文件和 GitHub 配置文件，并自动更新仓库中的公共证书指纹。`password.txt` 同时作为密钥库密码和私钥密码。

在 [writer 的 Actions Secrets 页面](https://github.com/bise86/writer/settings/secrets/actions) 中点击 **New repository secret**（已有同名项则更新），配置：

| Name | Secret 内容 |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | 私有目录内 `keystore.base64` 的完整文本 |
| `ANDROID_KEYSTORE_PASSWORD` | `password.txt` 的内容，去掉末尾换行 |
| `ANDROID_KEY_ALIAS` | `essaylens-release` |
| `ANDROID_KEY_PASSWORD` | 与 `ANDROID_KEYSTORE_PASSWORD` 相同 |

有 GitHub CLI 且已登录的机器，也可一次导入四项：

```sh
gh secret set --repo bise86/writer --env-file "$HOME/.local/share/essaylens/signing/github-secrets.env"
```

私有目录需要长期保留、备份和复用，不要在每次发布前运行生成命令。配置 Secrets、提交并推送匹配的证书指纹后，再推送版本 tag 触发发布。

```sh
git tag v1.0.0
git push origin v1.0.0
```

系统设置保存在设备本地 SQLite。

PDF 字体来源：[Noto CJK 官方简体中文字体](https://github.com/notofonts/noto-cjk/blob/main/Sans/Variable/TTF/Subset/NotoSansSC-VF.ttf)，通过 FontTools 固定为 400 字重、字形按 4 字节对齐的 TrueType 字体，资源以 Base64 JSON 内置，在打开批改页时延迟加载。可用 scripts/build-pdf-font.py 重建（开发工具需 fonttools 4.60.1）。

安装依赖时自动将鸿蒙 PDF 包中无 JSX 的 `.tsx` 规格文件改为 `.ts`，并去掉本地文件预览不使用的任意 HTTP 头类型、明确浮点字段，兼容 RN 0.77 codegen；鸿蒙分享包的 iOS 自动链接已禁用，避免重复 RNShare pod。
